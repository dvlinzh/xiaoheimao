WHAT

一个插件，三种身份

它是数据中枢、是 AI 能调用的工具、也是一只看得见的猫——三层互相独立，坏掉任何一层都不影响另外两层。

🗂️ 数据中枢

所有 AI 工具把想法写进同一个地方：~/.mind-board/。纯 JSON 文件 + 原子写盘，没有数据库、没有云端、没有账号。

🔌 MCP 工具

三个标准工具——organize 整理、query 回看、control 管理。任何支持 MCP 的 AI 工具都能直接调用，一次接入到处可用。

🐱 桌宠壳

小黑猫蹲在任务栏，头顶的图标环告诉你哪些 AI 正在干活；点开漫画风面板，四层骨架一目了然，还能拖拽整理。

核心玩法：四层骨架

AI 把对话内容随手归入四层，聊天照常进行，沉淀悄悄发生。

ideas

想法

用户随口提到的念头、方向、需求

「要不要支持深色模式」
points

要点

聊明确的结论，可标记「已敲定」

「性能优先，先不做动画」✔
plans

方案

候选做法与当前采用（全局唯一）

「方案 A：本地缓存【采用中】」
gaps

缺口

没想清、没验证的点，AI 会主动追问

「并发写冲突怎么办？」
HOW

怎么做到的

核心思路一句话：把「聪明」放进数据协议，把「脆弱」隔离在可抛弃的壳里。 文件系统是唯一事实源，三条标准通道接入，AI 工具、钩子、桌宠互不依赖。

1

软约束注入，不烧上下文。会话开始注入一次完整协议；之后每轮只注一行「目标 · 各层计数 · 缺口」，比反复塞全文省约 95% 上下文。

2

目标漂移防护是硬的。AI 写入的目标与现状相似度过低时，中枢拒绝写入并要求 AI 先问你「要不要新建一块板」——prompt 管不住的，用协议机制管。

3

文件即数据库。没有服务、没有锁、没有迁移：原子替换保证崩溃安全，任何编辑器都能直接修数据，拷走目录就是完整备份。

4

壳坏了不伤数据。渲染层的猫、图标环、面板全部可以随时重写；AI 通道（MCP + 钩子）独立工作——这条经验来自上百次真实重启。

🔒

隐私：全程本地。想法、骨架、对话沉淀只存在于你电脑的 ~/.mind-board/ 目录里，不联网、不上传、没有遥测。删掉目录 = 数据彻底消失；拷走目录 = 完整迁移。

START

三步开始

需要：Node.js ≥ 18、Claude Code（或其他支持 MCP 的 AI 工具）、Windows（macOS 理论可用未测试）。

获取并启动

克隆仓库、装依赖（只有 Electron 一个大件），启动桌宠：

git clone <仓库地址>
cd mind-board-pet
npm install
npm start

接入 Claude Code

仓库已带好配置，首次使用批准 MCP 服务器即可：

.mcp.json        ← 三个工具
.claude/settings.local.json
                 ← 两个钩子

正常聊天

不用学任何指令。点一下猫，头顶图标环亮起，点芯片打开面板——之后正常对话，猫会替你记账。

单击猫 → 图标环
点芯片 → 思维板面板
拖拽条目 → 删除 / 标记已实现

常见问题

会打断我和 AI 的对话吗？

不会。整理是 AI 的「副业」：它先正常回答你，工具调用安静完成。每轮最多一行提醒，你几乎察觉不到它的存在——直到打开面板发现都记下来了。

AI 会不会乱记、记错？

协议要求：模棱两可的一律进「缺口」，不脑补；疑似换目标时中枢直接拒写，强制 AI 先问你。所有条目在面板里可视化，随手拖拽修正。

我用的是 Codex / Gemini CLI 怎么办？

它们的 MCP 配置里注册同一个服务命令即可——数据中枢按项目目录自动归档，所有工具共享同一块板子，互相看得见对方沉淀的内容。

多项目会混在一起吗？

不会。项目身份由工作目录推导，每个目录一块独立的板；图标环按工具分组显示，面板里可自由切换项目。

占用多少资源？

一个 Electron 壳（约 100–200MB 内存）+ 每轮一行文本的钩子。数据是几个小 JSON 文件，journal 超 1MB 自动轮转。
