# 思维板 · 小黑猫（mind-board-pet）

一只蹲在屏幕边上的小黑猫，同时看管多个 AI 工具（harness）的思维板。

你跟 AI 聊了一两个小时，结论、方案、疑问散在几十轮对话里——关掉窗口就没了，下个会话从零开始。
而且你往往同时用 Claude Code、DSH、Codex 好几个工具，每个只记得自己那一小段上下文。

这个项目把「对话中一闪而过的想法」变成**留在本地磁盘、跨工具共享、能回看能改的三维骨架**，
再用一只桌宠让它看得见、想得起、点得开。

概念移植自 [dsh-mind-board](https://github.com/dvlinzh/DeepSeek-harness-mindboard)，重定位为**跨 harness 共享的桌宠中控**。

---

## 一、从价值到实现的闭环

整件事是一条完整的数据回路，五步：

```
① 产生            你在对话里冒出想法、结论、方案、疑虑
   ↓
② 沉淀            agent 按注入的协议，归纳改写后写进三维九模块骨架 → ~/.mind-board/
   ↓
③ 感知            猫头顶冒一句「喵，记下了 +3」；要紧的事单独冒泡
   ↓
④ 介入            点猫 → 图标环 → 面板：改名 / 切换目标 / 拖拽删除 / 勾选完成
   ↓
⑤ 回流            每轮对话开头注入一行状态（目标 · 三维计数 · 未解缺口）
   ↓
   └──────────────→ 接回 ①，闭环成立
```

### 每一环为什么不能省

| 环节 | 省掉的后果 |
|---|---|
| **协议注入** | agent 不会主动整理，你得每轮手动喊一次 |
| **归纳改写 + 去重** | 骨架退化成对话流水账，看第二次就不想看了 |
| **猫的感知** | **整理是隐形的**——看不见的功能等于不存在的功能，你永远不知道它记了什么、什么时候记的 |
| **面板的介入** | 骨架只增不减，记错了没法改，很快就不再可信 |
| **状态行回流** | agent 每轮都要重读全量骨架，又贵又慢 |

### 猫在这个闭环里的位置

**它不是装饰，是第 ③ 步的唯一载体。**

没有一只一直在屏幕边上的东西，第 ② 步发生得再勤你也察觉不到，第 ④ 步那扇门就永远不会被打开。
反过来，把猫删掉，数据、面板、MCP、钩子全都照常工作——这恰恰说明：**猫的价值是注意力，不是功能。**
拿功能视角去评价一个注意力装置，得出的结论必然是「鸡肋」。

所以猫身上只有两件事值得投工时：**常驻可见**，和**说人话的通知**。呼吸、拎起摆动、双击连跳这些是拟真表演，好看但不产生信息量——它们已经被冻结，不再投入。

## 二、三维九模块：这个骨架为什么长这样

一份思维骨架最容易退化成两种东西：**流水账**（什么都往里塞）和**收藏夹**（塞完再也不看）。
三维九模块是对这两种退化的结构性防御——每一维回答一个不同的问题，且只回答那个问题。

| 维度 | 回答的问题 | 模块 | 记什么 | 建议条数 |
|---|---|---|---|---|
| **价值维 Why** | 为什么做 | 需求锚点 | 触发场景 / 痛点（当__情况下，遇到__） | 1–2 |
| | | 受众画像 | 为__情境下的__人 | 1 |
| | | 价值主张 | 一句话：通过__为__解决__ | 1 |
| **结构维 What** | 做成什么 | 功能拆解 | 模块名：一句话职责 | 3–7 |
| | | 骨架识别 | 删掉就垮的核心模块 | 2–4 |
| | | 边界定义 | 明确**不做**什么 | 2–3 |
| **路径维 How** | 怎么走 | 核心链路 | 流程一步（步骤名 → 输出） | 3–5 |
| | | 依赖与瓶颈 | 缺什么 / 卡在哪 / 没想清的点 | 1–3 |
| | | 反馈闭环 | 什么信息回流、触发什么调整 | 1–2 |

三条硬规则写在数据中枢里，不是靠自觉：

- **同层去重**：精确相同、或相似度 ≥ 0.7 视为同一条 → 更新而非新增。所以「同一个结论说三遍」不会变成三条。
- **目标熔断**：新旧目标相似度 < 0.25 且骨架非空时**拒绝写入**，置 `pendingNewTask`，要求 agent 先问用户「这是不是一个新目标？」。防止一次话题漂移把两个不相干的目标搅在一起。
- **原子写盘**：所有落盘走临时文件替换；每次变更追加 `journal.jsonl`，供桌宠动效消费。

`~/.mind-board/` 是唯一的数据根：删掉目录即清空，拷走目录即完整迁移，全程不出本机。

## 三、小黑猫的 UX

### 常驻形态

贴在屏幕右下角、任务栏上沿，脚底微微没入任务栏 8px（看起来像坐在上面而不是浮空）。
透明、置顶，**逐像素命中**：只有猫身不透明的像素吃鼠标事件，光晕和周围空白一律穿透给下层应用——
所以你可以在猫身上方正常点桌面图标，不会点到它。

### 姿态与睡姿状态机

| 姿态 | 何时出现 |
|---|---|
| 坐立 `idle` | 默认 |
| 拎起 `walk` | 拖拽中——手里拎着永远是走姿 |
| 趴卧 `rest` | 闲置 5 分钟 |
| 闭眼深睡 `sleep` | 趴卧再满 10 分钟，或整理模式关闭 |

呼吸是 2600ms 的慢波，**只做纵向**（脚底锚定、头顶起伏），横向宽度不变——否则猫看起来在「变胖变瘦」。
鼠标一碰到猫就把它唤醒，闲置计时归零。

### 手势

| 操作 | 行为 |
|---|---|
| **悬停** | 唤醒（重置闲置计时） |
| **单击** | 开关头顶图标环（等 280ms 确认没有第二击） |
| **双击** | 原地连跳三下 |
| **拖拽** | 拎起来——切走姿、身体绕头中心随手速摆动；松手贴边，脚底坐回任务栏 |
| **右键** | 菜单：整理模式 / 猫体型 / 思维面板 / 项目仪表盘 / 设置 / 隐藏 / 退出 |

### 图标环：从猫到面板的那一步

单击猫，头顶展开一条**朝左的 120° 扇形**芯片列。

- **圆心锚定在猫身上**（头左上 45%, 34% 处），半径随体型等比。所以换猫体型、拖猫换位置，环都跟着走。
- **芯片不是固定列表**，而是「最近 10 分钟内有写盘的 harness」。谁在用就显示谁，不用就不占地方。
- **状态语义**：整理模式关 → 整体压暗到 0.38；10 分钟内有写盘 = 运行中 → 主题色光圈。
- 原生 GDI+ 绘制，不加载网页——所以展开是瞬时的。

### 思维面板

点芯片打开对应 harness 的思维面板。

- **顶部**：项目名（点击改名）、☰ 项目总览、Aa 字体字号、关闭
- **目标栏**：当前目标用大字（点击改名），其余目标是纯文字行（点击切换），末尾虚线「新建」；超过 3 个折叠成「⋯」，选中后自动收拢
- **进度条**：已敲定要点（骨架识别）的占比
- **主体**：三大分区九模块的手风琴，每个模块带计数徽标和一句提示语（「删掉就垮的」「不做__」「缺什么/卡在哪」）
- **条目操作**：可拖拽到删除区、可勾选完成

面板是**按需出场**的 WebView2 窗：点开才加载，关掉即销毁释放内存。

### 头顶气泡：唯一的被动通知通道

猫头顶会冒一句短话，4 秒消失，同时把睡着的猫叫醒。文案按优先级，一轮只冒一条（防止刷屏）：

| 事件 | 冒泡 | 优先级 |
|---|---|---|
| AI 写入思维板 | 喵，记下了 +3 | 计数 |
| 目标切换 | 喵，换目标：___ | 提示 |
| 新项目接入 | 喵，新板子：___ | 提示 |
| AI 疑似换目标（熔断） | 喵？换目标？___ | **紧急** |
| 数据文件损坏 | 喵！数据损坏：___ | **紧急** |

`harness-join`、`task-deleted` 这类事件**故意不接**——接了猫就变成话痨，通知也就不值钱了。

### 托盘

图标常驻托盘，带同一套右键菜单。猫被隐藏后从这里找回，退出也走这里。
构造时窗底额外向下留了 20px，坐姿的尾尖和影子不会被窗口裁掉。

### 设计取舍

- **该用网页的才用网页**：猫和圆环是简单图形 → 原生画（Win32 分层窗口，桌宠品类二十年标准做法）；面板是排版密集型 → 网页，但按需出场。
- **逐像素命中的代价**：悬停在猫窗矩形范围内时，下层应用收不到点击。这是桌面宠物的标准取舍，换来的是「猫周围空白完全透明」。
- **全屏独占游戏会盖住它**：Windows 系统限制，所有同类方案都一样，不列为 bug；无边框窗口模式不受影响。
- **协议注入是软约束**：模型偶尔偷懒不调工具属正常。状态行每轮都在，会持续把它拉回来。

## 安装

把下面这段话直接发给你的 agent，让它代为完成：

```text
请帮我安装并启动「思维板·小黑猫」插件（https://github.com/dvlinzh/xiaoheimao）：

1. git clone https://github.com/dvlinzh/xiaoheimao.git 到本机任意目录（如 ~/mind-board-pet）
2. cd 进去后执行：npm install（Node.js ≥ 18，无需 Electron——原生壳仅 60 余 KB）
3. 构建并启动：npm run build:shell && npm start
   （屏幕上的小黑猫 + 图标环 + 思维面板，全部由 C# 原生壳 + WebView2 承载）
4. 接入 Claude Code（本仓库已自带配置，零改动）：用 Claude Code 打开这个目录，
   首次会提示批准 .mcp.json 里的 mind-board 服务器（三个工具：
   organize/query/control），批准后 SessionStart / UserPromptSubmit 两个钩子
   自动随 .claude/settings.local.json 生效，开始对话即自动整理
   注意：钩子与 MCP 受「整理模式」开关控制，右键猫 → 设置窗 可切换
5. 验证：正常聊几句话后，点屏幕上的猫 → 头顶图标环 → 点芯片打开思维面板，
   能看到本轮对话整理出的目标/想法/要点/缺口
6. （可选）DSH 集成：在 DSH 安装脚本 src/dsh/index.js 对应入口的 Cordis
   挂载方式见仓库 README「接入 DSH」节；或直接把本目录交给 DSH 宿主按
   junction + cordis.patch.yml 方式注册

装完告诉我结果，有问题把报错发我。
```

> 需要 Node.js ≥ 18（[nodejs.org](https://nodejs.org) LTS）。数据存于 `~/.mind-board/`，
> 全程本地；删掉目录即清空，拷走目录即完整迁移。

## 接入 Claude Code（已在本仓库配置）

1. `.mcp.json` 已注册 `mind-board` 服务器（`mind_board_organize` / `mind_board_control` / `mind_board_query` 三工具），首次使用时批准即可
2. `.claude/settings.local.json` 已挂两个钩子：
   - **SessionStart**：注入全量思维板协议（compaction 后自动重新注入）
   - **UserPromptSubmit**：每轮注入一行状态（目标 · 三维计数 · 未解缺口）
3. 钩子和 MCP 受「整理模式」开关控制——右键猫 → 设置窗可切换

## 接入 DSH（多入口设计：一份数据核心，四个接入壳）

```
入口 A  MCP stdio（任何 harness）       src/mcp/server.mjs
入口 B  Claude Code 钩子               src/hooks/*.mjs
入口 C  C# 原生壳（猫 + 面板）          shell-win/PetCat.cs
入口 D  DSH Cordis 插件壳              src/dsh/index.js   ← DSH 生态用这个
```

四个入口共用同一份 `~/.mind-board` 数据与同一套 store 原子写盘；DSH 会话自动建 `t_` 任务，
与 Claude Code 侧的目录项目（`p_`）在同一数据根互不冲突。

**方式一：Cordis 插件壳（推荐，DSH 原生体验）**

```powershell
.\scripts\install-dsh.ps1        # junction ×2 + cordis.patch.yml 注册，然后完全重启 DSH
```

装完在 DSH 输入框右侧点**脑图标**开启整理模式（entry D 的开关门禁）。喊「喵喵喵」可唤起桌面猫。

> ⚠️ 与原有 `dsh-mind-board` 插件**二选一**：两者行为都是整理注入，双装会双份提醒。
> 安装脚本会检查并提示。

**方式二：MCP 注册**（DSH 若支持外部 MCP server 配置）

```jsonc
{ "command": "node", "args": ["<本仓库>/src/mcp/server.mjs"], "env": { "MIND_BOARD_HARNESS": "dsh" } }
```

agent 引导需在 DSH 侧补充（没有 CC 那样现成的钩子）；数据写入与面板展示照常可用。
