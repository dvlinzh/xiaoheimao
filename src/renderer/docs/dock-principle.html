图标环组件 · 原理与技术图解

dock（图标环）—— 点猫弹出、以猫头为圆心扇形排布的 harness 芯片。本文拆解它的数据来源、排列算法、命中机制与防御性设计。

① 组件全景：一个透明的置顶小窗

图标环不是猫窗的一部分——它是一个独立的 Electron 窗口，叠在猫头上方。

② 工作循环：3 秒一次的数据流水线

dock 渲染层没有自己的数据——它每 3 秒从本地 HTTP 服务拉一次总览，聚合成「每个 harness 一枚芯片」。

  1. 拉取 GET /api/overview → 44 个项目记录（含 id / harnesses / counts / liveAtMs）
  2. 聚合：项目 → harness 按 harnesses[] 分组累加：gaps 求和、newest 取最新 updatedAt、live 取最新文件 mtime。43 个 dsh 项目合并成 1 枚鲸鱼芯片。
  3. 签名比对（防重建抖动） sig = 每个harness的「存活位 + 红点位」拼接。与上次相同 → 直接 return，DOM 不动——防止 3 秒轮询把用户正按着的芯片换没。
  4. 重建 + 上报芯片矩形 innerHTML 重建芯片 → 把每个芯片的客户区矩形（±30px 热区）发给主进程 → 换算屏幕坐标 → 推给猫窗做命中排除（见 ④）。
  5. 显示时强制刷新 visibilitychange → 清签名 → 立即 refresh。隐藏期 Chromium 把定时器节流到几十分钟一次，靠它保证弹出来的环永远是新鲜的（曾因此整晚显示空环）。

③ 排列算法：以猫头为圆心的 120° 非对称扇形

圆心永远对准猫头中心。四个槽位按角度预算在左侧 120° 扇区（-168° → -50°），间距不等、非镜像——n=2 时两芯片一高一低，读得出「绕着头」的弧线。

④ 状态机与点击路由

每枚芯片有三种状态；点击能落到芯片，靠的是「穿透 + 矩形排除」双机制。

状态条件视觉
st-on 整理中整理模式开 且 10 分钟内有项目文件写盘正常色 + 主题色恒定光晕（--glow 变量按芯片注入）
st-idle 待命装过插件但超过 10 分钟无写盘灰度化（grayscale + 微降亮度）
st-off 模式关用户在设置里关了整理模式深度灰化

⑤ 防御性设计：每一个都是真实事故的修复

机制防的事故原理
签名比对3 秒轮询重建 DOM，把正按着的芯片换掉 → 点击丢失keys+状态拼签名，不变不重建
pointerdown 触发click 等 mouseup 期间恰好赶上重建按下即触发，500ms 防重入
visibilitychange 强刷隐藏期定时器被节流到几十分钟一次，显示旧 DOM（曾整晚显示空环）show 时清签名立即刷新
mouseout 悬停恢复重建合成 mouseout 误杀悬停态，静止光标第一次点击必穿透下一帧按 .chip:hover 真实状态恢复
moveTop 随定位猫窗 setPosition 反压 dock，点芯片点到猫dock 每次定位重新压顶
芯片矩形排除芯片区与猫窗重叠的 z-order 竞争猫窗命中检测对上报矩形一律穿透
1.2s toggle 防抖快速连点猫，环 show→hide 闪没刚弹出 1.2s 内的再点忽略
