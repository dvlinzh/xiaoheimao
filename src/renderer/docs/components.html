①数据中枢 store.mjs

整个插件唯一的「事实源」：一个纯 Node 文件、零依赖，被 MCP server、本地 HTTP 服务、冒烟测试三方直接 import。 它定义了四层骨架的合并规则、目标漂移防护、原子写盘与事件流。

organize() —— 每次整理的决策流水线

磁盘布局与项目身份

~/.mind-board/
├── projects/        项目档案：id = "p" + hash(小写cwd)
│   └── pe4ths8.json  { id, title, projectDir, harnesses[], state,
│                       pendingNewTask, msgCounter, updatedAt }
├── skeletons/       骨架：{ goals[], currentGoalId }
│   └── pe4ths8.json  goal: { id, title, goal, ideas[], points[], plans[], gaps[] }
├── journal.jsonl    事件流（动效消费）
└── settings.json    mode / 整理频率 / 字号 / 皮肤 / 窗口记忆…

关键点：项目身份由「工作目录的稳定哈希」推导 → 多项目天然隔离，
同一目录被多个 harness 打开时 harnesses[] 追加登记（首见不覆盖）。

②AI 接入层：Hooks + MCP

两条通道把任意 MCP 兼容的 AI 工具接进中枢：钩子是「AI 被动接收」的软约束（每轮一行状态）， MCP 是「AI 主动调用」的硬入口（三个标准工具）。

一轮对话的完整时序

MCP 三工具一览

工具作用关键参数返回
mind_board_organize增量整理四层骨架cwd（必填）+ goal/goalTitle + ideas[]/points[]/plans[]/gaps[]{ ok, applied:{层:新增数, 层_updated:更新数} }；漂移时 isError
mind_board_query读当前骨架（紧凑文本视图）cwdMarkdown：目标/想法/要点/方案/缺口
mind_board_control宿主动作action: new-goal / switch-goal / archive / remove-item / toggle-* / choose-plan …{ ok } 或 { ok:false, message }

③桌宠猫窗：渲染与交互

一个 190×220 的透明置顶窗，画布上逐帧重绘猫。难点全在两件事：让动画活着（后台窗会被节流）和 让点击只落在猫身上（逐像素命中）。

渲染管线（skin-cat.js · 每帧）

交互链路（为什么猫总是「可看不可点」的解法）

环节机制参数
穿透切换主进程 100ms 轮询光标 → IPC cursor-pos → 渲染层 overPet 判定 → set-ignore-mouse-events 切换不依赖系统鼠标钩子（钩子会被全屏应用摘除且永不恢复）
单击移动 <6px 且 <450ms → 280ms 定时器 → 切换图标环280ms 容忍双击转颠球
拖拽主进程判定移动 ≥10px → 猫变拎起姿态 + 三向吸附（左缘/右缘/任务栏）阈值 10px：3~6px 的手抖不会误判
双击第二次击clear定时器 → 连跳三下—
右键设置窗贴猫弹出—
诊断每 5s 心跳：事件计数 / 穿透状态 / 命中表状态 → electron.log交互失联时定位断层

④思维板面板

380×660 起步的透明可缩放窗，优雅黑令牌 + Georgia 衬线。数据全部来自 /api/skeleton 与 /api/action，自身零状态（除图钉/字体偏好存 localStorage）。

DOM 结构与四层渲染

拖拽删除 / 标记已实现（状态机）

mousedown(条目) ──→ drag = { sx, sy, active:false }
  │ 移动 ≥ DRAG_MIN(6px)
  ▼
active = true ──→ 按住条目半透明(.drag-src) + 幽灵卡随光标(.drag-ghost)
              + 底部滑入两区：[✓ 标记已实现]（仅想法） [🗑 删除]
  │ mousemove
  ▼
armZone( zoneAt(e) )   // 命中判定走坐标（zoneAt），分区不拦鼠标
  │ mouseup
  ▼
zone = zoneAt(e) ──┬── "del"    → POST /api/action remove-item / remove-goal
                   └── "toggle" → POST /api/action toggle-done（仅 canToggle）
 任意窗口 blur / 鼠标离开文档 → endDrag()（清幽灵卡 + 收起两区）

两区是 .dz-stack（fixed 居中容器）的 flex 子元素——曾经每个分区自己 translateX(-50%) 居中，容器化之后忘了删，armed 分区会左滑半个身位（你报告过的「漂移」即此）。

钉住与自动收回

机制规则
默认钉住mb.pinned ≠ "0" 即视为钉住——面板打开后点别处/拖猫都不消失；图钉或 Esc 显式关闭
blur 收回（未钉时）show 后 1.2s 内的 blur 忽略（Windows 对非前台进程会强制收回焦点，造成「闪开即关」假象）；超时后真失焦才 hide
宽限基准刷新每次 show 事件都刷新 bubbleShowAt——覆盖同窗口复用再唤起的场景
尺寸/位置记忆拖边缩放（.rz 抓条 → 主进程跟随光标）、拖动位置 → 防抖落盘 settings.json，重启延续
